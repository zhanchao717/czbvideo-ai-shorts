# 流水线详细规范（workflow.md）

从「柴主编」日更管线 v2026-08-30 提炼。适用于任何"单热点 + 单结论 + 可执行动作"的知识类竖屏短视频。

## 1. 账号承诺与选题结构

一期视频只回答一个具体问题。滚动 14 期的结构配比：

- **60%**：免费、省钱、避坑的 AI 工具与工作流
- **30%**：Agent / 自动化的可执行教程
- **10%**：会改变普通用户行动的重大热点

比例是实验目标，不为凑比例生产低质内容。纯融资、估值、榜单、未经证实的泄露默认不做；只有能回答"这会让普通用户今天改变什么"且证据充分时才进候选。

一天做多期时：**各期必须不同质**（不同支柱，或同支柱不同角度），四类钩子也不得连续两期重复。

## 2. 候选评分门禁（≥70 才生产）

| 维度 | 分值 |
|---|---:|
| 对普通用户的实际价值 | 30 |
| 是否符合账号承诺与系列连续性 | 20 |
| 官方证据与可用视觉素材 | 20 |
| 能否给出一个可执行动作 | 15 |
| 24–72 小时时效与讨论信号 | 10 |
| 合规和事实风险 | 5 |

评分和理由写进 `sources.md` 末尾，落选候选也记一笔（防止三天后重复调研）。

## 3. 事实核验纪律（sources.md）

每条事实的格式：**结论 + 一手来源 URL + 定性**。

- 时效、价格、模型能力、安装方法必须先查官方公告 / GitHub Release / 官方文档 / 论文；媒体转述不覆盖一手来源。
- 数字必须标口径：`约 5%（Cursor CEO 公开口径）`、`39,000+（官方博客自述，无独立审计）`。
- 官方自述 ≠ 实测：没亲手测过的功能写"官方自述，未实测"，绝不写"我试了"。
- 无法核验的数字、排名、绝对化描述直接删除。
- 每期单列「编辑判断与禁项」：明确本期不说什么（如不写 star 数、不下"谁比谁好"结论、不渲染失控论）。
- 实时数据（star 数、排名）用模糊口径"几天几百星（截至 2026-09-01）"，不咬死。

## 4. 脚本规则

**只允许一个核心结论**，按信息复杂度选时长档位：

- 快速工具 / 避坑 / 热点判断：25–35 秒，约 110–170 个非空白字符
- 教程 / 对比 / 机制解释：35–45 秒，约 160–210 个非空白字符

结构 4–5 段，可伸缩：

1. 0–2 秒：一句完整可听懂的结果 / 错误 / 对比 / 问题。不说"大家好"。
2. 2–10 秒：关键事实 + 来源锚点。
3. 中段：只解释一个机制 / 步骤 / 取舍。
4. 后段：谁该行动、怎么行动、谁不用行动。
5. 结尾：补限制，给下一步或明确判词。禁止空泛的"关注不迷路"。

**开头四类轮换**（连续三期不同句式）：结果型 / 避坑型 / 对比型 / 问题型。

脚本的"口播文"与"画面文"分离：英文专名、复杂术语只出现在画面，口播用中文动词替代（例：不念"goal 工具的 update_goal 命令"，念"把目标挂上，断了能续"）。

### 文案质检四件套（或等效人工检查）

1. **hook**：开头不依赖封面标题、5 秒独立成立、制造悬念而非给答案
2. **resonate**：痛点当天可感、利益点可带走
3. **ai-check**：无营销腔 / 日报腔 / 装饰性排比 / 空泛归因
4. **humanizer**：口语颗粒、动词开头短句、无模板连接词

前提是**不改事实含义**。质检记录落 `dbs-review.md`。

## 5. 配音与时间轴

用 `scripts/minimax_tts.py`（MiniMax T2A）逐句合成：

```
python3 scripts/minimax_tts.py 01.txt 01.mp3 --subtitle-output 01-words.json \
  --voice-id male-qn-qingse --model speech-2.8-hd --speed 1.08 --emotion calm
```

- 每句一个 txt/mp3/words.json，命名 `01..05`
- 冷静的科技媒体主编感：speed 1.08 + emotion calm，不喊口号
- **必须**拿 `--subtitle-output` 的词级 JSON——它驱动逐词字幕和嘴型

然后 `scripts/build_chai_timeline.py <episode_dir>` 生成：

- `audio_meta.json`：各句时长 + 词组（句内相对时间）
- `caption_groups.json`：全局字幕组（遇句读标点收束一条）

场景时长 = 该句配音时长 + 0.5s 叠化余量；末场景 = 配音时长。总时长必须落在所选档位。

## 6. 视频工程（HyperFrames 契约）

任何 HTML→视频渲染器都可复现，契约是：

- 一个 `index.html` 主合成，DOM 用 `data-start` / `data-duration` / `data-track-index` 声明时间轴；场景子合成用 `data-composition-src` 引文件
- 动画全部 **seek-safe**：`gsap.set/fromTo/to` 挂在 paused timeline 上，禁用 random / Date.now / CSS infinite 动画
- 音频是合成的一部分（`<audio data-start=...>`），渲染器负责混流
- 渲染时把自带 ffmpeg 包装目录放 PATH 最前（或保证系统 ffmpeg 可用）

详细版式坐标、场景模板、封面排版见 [design-system.md](design-system.md)。

## 7. 渲染后验收（三脚本 + 独立评审）

```bash
# 1) 规格与运动：1080×1920@30 h264/aac、时长档、长静帧/黑帧/中段静音
python3 scripts/chai_check_motion.py final.mp4 --json pkg/motion-report.json

# 2) 锚点帧：每字幕组 2 帧 + 数字卡点帧 + 每场景开头 3 连拍
python3 scripts/chai_qa_frames.py final.mp4 caption_groups.json --out pkg/qa-frames

# 3) 视觉快检（可选）：抽静止态帧 + 三封面，读图查错字/裁切/重叠
python3 scripts/chai_visual_review.py pkg --frames 1
```

三脚本全 PASS 后，锚点帧 + 封面交**独立评审**（未参与制作的 subagent 或全新会话），按 P0/P1/P2 出报告写 `quality-report.md`：

- **P0**（未清零不交付）：错字、事实错误、字幕与画面张冠李戴、文字遮挡/截断/出画、铭牌异常、封面三比例不一致
- **P1**（应修）：孤字折行、断词、过小字号
- **P2**（记录不阻塞）：风格建议

**评审结论必须逐条对照契约甄别**：评审者看不到配置，常用 primaryContent 线去判字幕带"越界"（实际有专用 speechBar 带区），或把模型知识截止导致的"未来日期"当错误。已知豁免：转场帧瞬态交叠、入场半透明、coined 表达、当天之前的日期。

## 8. 复盘

每期填 `performance-record.md`（发布前字段 + 空白 24h/72h 回填区，禁止用日汇总冒充单条表现）。每 7 天复盘一次，**一次只调一个变量**（钩子类型 / 时长档 / 皮肤 / CTA），北极星是"每千次播放新增关注"。
